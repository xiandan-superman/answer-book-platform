# 一键问题反馈与诊断接收设计

## 用户体验

普通用户不填写表单、不选择文件、不选择范围，也不处理隐私勾选。所有入口都是一次点击，但按钮放在问题发生的位置，由入口自身携带上下文：

- 每道答案或练习题旁的“反馈此题”绑定当前题号、答案、证据、审计结果及生成调用；
- 任务执行、任务详情和导出区域的“反馈当前任务”绑定当前任务、阶段和失败链；
- 顶部“反馈页面问题”绑定当前页面、最近操作、失败请求和前端异常；
- 用户点击前如果恰好选中了文字，自动把选中段落作为定位线索；没有选中文字也能直接提交。

点击后立即开始收集和提交，不再弹出第二层问题类型选择。

- 接收端在线：显示“反馈成功，问题编号 AB-...”。
- 接收端离线：显示“反馈已保存，将自动提交”，后台按退避策略补传。
- 同一问题重复点击：更新同一问题的发生次数，不产生重复文件。

页面固定说明“将发送与当前问题相关的题目、答案和模型调用上下文；不会发送 API Key、密码或无关任务内容”，说明不要求用户再次确认。

## 反馈内容边界

### 长任务

时间范围不是任务诊断的边界。任务无论运行十五分钟、六小时，还是跨重启恢复，都发送同一个任务 ID 对应的完整轻量生命周期：

- 创建、排队、开始、暂停、恢复、阶段切换、重试、取消、完成或失败；
- 每个阶段的开始时间、结束时间、耗时、结果和错误码；
- 模型调用按阶段/模型聚合后的次数、成功数、失败数、超时数和耗时；
- 与最终错误关联的请求、模型失败及异常堆栈详情；
- 当前任务进度文件的字段白名单摘要，不发送阶段输出内容。

详细日志只取“错误邻域”：匹配当前 task_id、request_id、support_id 的记录，以及错误前后有限条记录。这样保留完整因果链，同时避免随任务时长无限增长。

### 非任务问题

没有关联任务时，发送当前及上一次浏览器会话的有界语义操作轨迹，包括页面跳转、按钮动作、接口路径、耗时、HTTP 状态和前端异常。只记录控件身份，不记录输入框内容。

### 相关内容胶囊

反馈不能只排查程序异常，还必须能够排查答案质量和模型行为。程序根据当前页面、当前任务、最后交互题目、`active_item`、失败调用和质量审计结果，自动选择最小的相关内容胶囊，不要求用户选择：

- 答案质量问题：相关原题、实际采用的教材证据片段、生成答案、结构化答案对象、确定性校验和质量审计结果；
- 模型没有完成：完整系统/用户消息、模型与关键参数、实际发送的图片、响应文本或错误响应、每次重试及降级顺序；
- 图像理解或作图问题：实际传给模型的相关图片、图像哈希、尺寸、媒体类型和模型返回；
- 页面或网络问题：操作轨迹、请求关联和异常栈，不附加无关题目内容；
- 无法定位到单题时：只附任务内失败调用、审计标记项和最终失败阶段，不打包整本教材或全部输出。

内容胶囊的选择结果写入清单，管理端能看到“为何包含这些内容”和“哪些内容因容量边界被省略”。

### 模型调用诊断副本

现有 `model_calls.jsonl` 只有模型、阶段、耗时和结果等元数据，不能还原 Prompt 与回复。从启用本功能的版本起，每次模型调用额外保存一个任务关联的压缩诊断副本：

- 请求消息、模型参数、响应文本或错误响应；
- `task_id`、`stage`、`operation`、`active_item`、`call_id` 和重试关系；
- 图片本体不重复复制到每个调用，只保存任务内资源引用、哈希和发送顺序；生成反馈包时再读取相关图片；
- 成功调用按“每个阶段/题目保留最后一次”压缩归并，失败调用优先保留；
- 每个任务诊断副本总量上限 25 MiB，全局上限 256 MiB；达到上限时先删除已聚合的旧成功调用，不删除当前失败链；
- 删除任务时同步删除其调用副本；完成任务的调用副本保留 30 天，之后只保留聚合元数据。

旧版本已经发生、且当时未持久化的 Prompt 和回复无法事后完整还原，反馈包必须明确标记 `model_context_unavailable_for_legacy_call`，不能假装上下文完整。

### 始终排除

- API Key、密码、Authorization 和接收端凭证；
- 与当前任务、题目、证据或模型调用无关的 HTTP 请求正文和 URL 查询参数；
- 与当前任务、题目、证据或模型调用无关的教材、真题、上传文件和输出文件；
- 与当前问题无关的 Prompt、模型请求、模型回复和输入文字；
- 本机绝对路径和操作系统用户名。

## 关联与问题指纹

每个浏览器会话、用户动作、HTTP 请求、后台任务、模型调用和异常分别具有 session_id、action_id、request_id、task_id、call_id 和 support_id，并在结构化日志中互相关联。

问题指纹由下列稳定字段生成，不包含随机编号和时间：

- 应用版本和诊断结构版本；
- 页面、业务动作和失败接口；
- 错误类型、错误码和标准化错误信息；
- 任务类型、任务阶段和模型阶段；
- 崩溃位置或后端异常栈顶位置。

接收端按问题指纹归组，按上传内容 SHA256 判断完全重复。相同问题只保留一份最新诊断包，在 SQLite 中累计 occurrence_count、first_seen、last_seen、版本分布和设备分布。已解决问题再次出现时自动重新打开。

## 客户端容量和可靠性

- 在磁盘临时文件中逐项写入 ZIP；禁止在内存构造完整 ZIP。
- 上传以 64 KiB 数据块流式发送；禁止 read_bytes 后整体上传。
- 不含图片的压缩包目标不超过 2 MiB；包含相关内容与图片时目标不超过 8 MiB，硬上限 12 MiB。
- 各分区单独限额：清单 32 KiB、生命周期 256 KiB、前端轨迹 256 KiB、错误邻域 1 MiB、相关文本内容 3 MiB、相关图片 6 MiB、模型聚合与失败详情 2 MiB、环境摘要 64 KiB。
- 超过分区预算时先聚合成功记录，错误和阶段边界优先保留，并在清单写明截断情况。
- 离线队列最多保留 5 个不同问题、合计不超过 25 MiB；相同指纹直接替换旧包。
- 接收端确认 SHA256 并返回问题编号后，客户端立即删除已发送 ZIP，只保留很小的提交回执。
- `.part` 临时文件超过一小时自动清理；写入和队列索引采用原子替换。
- 重试采用退避和抖动；Tailscale 或接收端离线不会阻塞用户业务操作。

## 接收端容量和安全

接收端分为两个监听面：

- Tailscale 地址只提供上传和健康检查，不提供问题内容浏览；
- `127.0.0.1` 本机管理页用于查看、标记已处理、重新打开和删除。

接收流程：

1. 校验 Tailscale 来源和提交凭证；
2. 以 64 KiB 块写入随机 `.part` 文件，超过 12 MiB 立即终止；
3. 校验上传 SHA256、ZIP 文件数量、成员路径、成员大小和总解压大小；
4. 拒绝路径穿越、符号链接、ZIP bomb、损坏包和未知结构版本；
5. 在 SQLite 事务中去重并原子移动为正式文件；
6. 完全重复立即删除临时文件；同指纹问题用最新包替换旧包。

SQLite 只保存清单、状态和聚合数据，列表分页读取，不扫描或解压全部 ZIP。接收线程设并发上限和来源速率限制，防止同一客户端占满内存、磁盘或线程。

## 自动清理

- 损坏、不完整和校验失败的上传不入库；临时文件一小时后清理。
- 同一问题只保留最新一份原始诊断包；历史发生信息存 SQLite，不复制 ZIP。
- 已处理问题的原始包保留 7 天；未处理问题的原始包保留 30 天。
- 原始包删除后保留 180 天轻量问题摘要和发生次数，用于观察复发趋势。
- 默认原始包总容量上限 512 MiB；达到 80% 开始清理已处理包，达到硬上限继续清理最旧原始包。
- 自动清理不删除未到期问题摘要；空间不足仍无法恢复时拒绝新上传并返回明确状态，客户端继续排队。
- 管理页可立即删除单个问题；删除动作同步清除 ZIP 和数据库详情，只保留必要的审计时间与编号。

## 管理页

管理页以“问题”而不是“文件”为中心，默认显示：

- 问题编号、摘要、首次/最近发生时间、发生次数；
- 影响版本、设备数量、当前状态和是否仍有原始诊断；
- 归纳后的完整任务阶段时间线、失败点和关联请求；
- 标记已处理、重新打开、立即删除操作。

原始 ZIP 是二级入口，不在首页罗列文件。

## 必须验证的异常场景

- 六小时任务、跨进程重启和断点恢复仍有完整阶段时间线；
- 浏览器问题没有 task_id 时仍能提交上一会话轨迹；
- 接收端离线、Tailscale 断开、上传中断和服务重启不会丢队列；
- 同一问题连续提交一百次只保留一个 ZIP；
- 一百个并发上传的进程内存保持有界；
- 超大包、ZIP bomb、路径穿越、损坏包和伪造校验被拒绝；
- 诊断包中搜索不到测试用 API Key、密码、无关任务内容和绝对路径；相关题目、答案、证据、Prompt 和模型回复必须存在；
- 达到 512 MiB 配额时按规定清理，不无限占用磁盘；
- 已处理问题到期自动清理，复发时自动重新打开；
- 接收确认前客户端不删除，确认后不保留重复 ZIP。
