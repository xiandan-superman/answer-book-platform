# VNext-R2 融合实施与验证报告

> 版本：`8.26-vnext.r2`  
> 日期：2026-08-19  
> 状态：独立第三版最佳候选；已完成零付费验证，尚未执行用户暂停的付费模型回归。

## 1. 结论

VNext-R2 不是“线上版加补丁”，也不是“本地优化版简单修复”。它以本地优化版的高质量能力栈为主体，只移植线上真实任务已证明有价值的容错与候选保留方式，并增加两版都缺少的图片交付、分级验收和成本账本。

当前可以确认：

- 相比线上版，R2 保留了本地版在真实 DOCX 输入、复杂题结构、检索证据、确定性专业图、检查点恢复、表达式/Word 公式、批次隔离和质量治理上的大优势。
- 相比本地优化版，R2 不再因单题可修复问题把完整结果整批作废；原题图与答案图分开治理；模型响应不会在固定墙钟时限到达时被后台线程强杀；所有模型调用可按任务归集 token、失败浪费、耗时与可核算费用。
- R2 的代码与零付费回放结果优于两个原版本，但“模型实际答案质量与真实费用”仍必须经过最小付费 P2-01～P2-05 smoke test 后才能作最终生产结论。

## 2. 双向优势来源

| 模块 | 保留/吸收内容 | 来源 | 为什么保留 |
|---|---|---|---|
| 真题与生题输入 | 图片锚点、OMML、表格顺序、综合题与嵌套小问、ZIP 目录项过滤 | 本地优化版 | P1 六文件全部胜出；线上曾在真实 DOCX 出现 `word/media/media` 确定性失败 |
| 检索与证据选择 | BM25、上下文续段、规范语义行、已确认候选检查点、8192 token 有界选择 | 本地优化版 | 真实任务中更快，且证据约束更完整 |
| 答案生成 | 自适应 token/思考/超时、计算合同、证据回绑、表达式提升、按作答单元组织 | 本地优化版 | 这是本地大规模优化的核心质量收益，不做回退 |
| 候选保留 | 全题覆盖即可继续进入质量治理；问题/兜底降为待复核候选 | 线上已验证优势 + R2 分级 | 避免 P2-01、整卷任务中正确成果因格式残留全部丢失 |
| 模型路由 | 视觉模型先读原图，同时保留用户所选文本模型作为显式后备 | 线上稳定性思路 + R2 修复 | 修复本地版图片题中用户模型被静默排除的问题 |
| 模型响应 | 取消进程内硬墙钟强杀；Responses 流可在缺少 completed 事件时仅回收完整 JSON | 第一版 VNext/R2 | 避免 120 秒到点丢弃正在返回的正确结果，同时拒绝残缺 JSON |
| 图片合同 | `source_image_required` 与 `answer_figure_required` 分离；最终 Word 和验收分别核对 | R2 新增 | “模型看过原图”不再等于“Word 已交付原图”；也不会把原题图误当作答案作图 |
| 专业作图 | 能力注册表、确定性 renderer、程序科学规则、视觉 QA 只作为非确定性证据 | 本地优化版 | P2-03 本地 3:59 获得科学结构正确图，线上 11:54 生图仍错 |
| XRD 路由 | “粉末衍射峰”任务意图优先于“体心立方”实体词；BCC/CsCl 有序化用确定性消光峰位合同 | 线上语义路线 + 本地 renderer + R2 新合同 | 修复 P2-04 路由到晶胞图的 P0 问题，又不采用昂贵自由生图 |
| 质量治理 | capability registry、selective review、shadow quality、算术一致性、交付闭环 | 本地优化版 | 线上版缺少这套可扩展治理能力 |
| 生题系统 | 批次合同、槽位补齐、部分失败隔离、结果装配、断点与任务队列 | 本地优化版 | 防止一个批次失败覆盖已生成题目 |
| 长任务容错 | 练习分析/规划/生成 watchdog 改为分阶段可配置长时限 | 线上长任务经验 + R2 | 不追求极短耗时，但不允许正常长任务被 5～60 分钟固定门误杀 |
| 成本核算 | 每次调用落盘 task/stage/model/outcome/elapsed/usage；失败 token 单列；可配置合同单价 | R2 新增 | 最终选型可比较总成本、失败浪费、单位合格任务成本，而非只看模型汇总下限 |

R2 目前含 `116` 个 Python 应用模块；相对线上快照多 `42` 个模块。能力注册、质量治理、表达式渲染、检查点/交付/遥测、生题批次与字体运行时等本地新增模块均被保留。

## 3. 本轮修复的关键缺陷

### 3.1 用户可感知

- 完整候选不再因为可修复公式/解析问题变成“无文件”；结果明确标为正式候选或待复核候选。
- 图片题最终 Word 会带入“原题图”；若答案还要求作图，则必须另有“图示”，不能互相冒充。
- 作图题、含作图小问的计算题、文字明确要求画图但题型标签遗漏的题，都能进入作图规划。
- P2-03 的旧重复图在执行边界去重为 1 张；负晶面指数使用晶体学上划线。
- P2-04 不再画晶胞替代 XRD 峰图；无序态共有峰和有序化新增超结构峰清楚区分。
- 长任务仍可能耗时较长，但不会在固定 120 秒或过短 job watchdog 到点后静默丢弃有效响应。

### 3.2 程序与风险

- 生成阶段把“流水线能否继续”与“是否可作为正式结果”拆成两个状态；缺题仍阻断，质量问题进入后续治理。
- 最终验收新增图片交付硬检查：原图缺失、必要答案图缺失分别报告。
- 混合“计算＋作图”父题仍走计算排版分支，公式和解题步骤不会因一个作图子项被过滤。
- 模型调用上下文可跨并发 worker 传播，成本记录可正确归属于任务与阶段。
- 成本账本不保存 prompt、response 或密钥，只保存固定元数据和 usage。

## 5. 成本核算口径

R2 每次模型调用记录：任务、阶段、用途、服务商、模型、开始/结束、耗时、结果、输入 token、输出 token、推理 token、服务商费用（若返回）。

- 失败/超时调用的已知 token 记为 `known_waste_tokens`。
- 成功调用在最终产物引用归因完成前记为 `unclassified_success`，不虚报成“有效成本”。
- 服务商直接返回费用时优先采用；否则读取 `config/model_pricing.local.json` 的实际合同价估算。
- 缺 usage 的请求单独计数，不用 0 冒充。
- 任务交付生成 `模型调用汇总.md` 和 `模型调用明细.jsonl`。

本轮遵照用户要求没有发起付费调用，因此报告只验证“可完整记录和核算”，没有伪造 R2 实际费用。

## 7. 独立性

R2 目录不含线上/本地运行任务、缓存、日志、输出、密钥或 `.env`；原线上版、本地优化版和第一版 VNext 均未被修改。R2 后续可作为第三版单独启动、测试和打包。
