## 目标一：支持每道原题多个核心知识点

1. 原题分析时，每题的 `knowledge_points` 应列出实际涉及的全部核心知识点，不限制为一个。
2. 范围确认后，蓝图输入必须包含每道原题的题干摘要、题型、难度和完整 `knowledge_points`。
3. 蓝图每项增加 `required_knowledge_points`，明确正式生题必须考查的知识点组合：
   - 整体综合：在整套蓝图中合理分配或组合知识点，并完整覆盖所选范围。
   - 一一对应：一道原题对应一道新题，保留该原题完整知识点组合。
   - 逐题变式：一道原题生成 N 道变式，每道均保留完整知识点组合。
4. 正式生题输入必须包含 `required_knowledge_points`；输出的 `knowledge_points` 必须完整匹配，否则不能通过校验。
5. 不把多个知识点自动拆成多道题，不改变现有题量计算方式。
6. 旧蓝图缺少该字段时，从对应原题或知识单元的 `knowledge_points` 自动补齐。

## 目标二：增加“正式生题时参考来源材料”开关

增加统一字段：

```text
include_source_content_in_generation: true/false
```

默认开启，并保存到任务、蓝图和历史记录中，单题重生继续沿用。

### 流程要求

- 原题或知识材料分析：始终读取来源材料，不受开关影响。
- 蓝图生成：始终使用已确认的分析结果和必要摘要，不受开关影响。
- 正式生题：由开关决定是否继续传入原始内容。

### 开启时

- 按题生题传入原题题干、原图和原表格。
- 知识点生题传入教材原文、公式、图表等相关材料。

### 关闭时

- 不传原始题面或知识材料，只传蓝图、`required_knowledge_points`、必要定义、公式、适用边界、题型、难度和变化要求。
- 页面提示：关闭后题目发散性更强，可能与原题结构、解题路径或教材具体表述存在较大差异，不适合严格平行题、原题变式及依赖图表的任务。

## 验收要求

- 覆盖知识点生题。
