> 版本：`8.26-vnext.r3.1`

> 状态：待确认，未授权开始新的付费运行。

## 1. 要回答的核心问题

本轮不再追求“某一道特例终于通过”，而是验证 R3.1 能否作为通用学科平台的后续基线：

1. 使用者是否能感知到答案质量、图像理解、排版和等待体验的改善。
2. 程序是否能分清“模型答错”、“程序损坏正确答案”和“外部服务失败”。
3. 单题中的改进是否能扩展到多题、多题型和整卷，而不引入跨学科副作用。
4. 质量收益需要多少耗时、token、重试和人工复核成本。

## 6. 阶段 D：用户旅程、恢复和发布决策

### 6.1 使用者角度

| 环节 | 关注什么 | 验证什么 |
|---|---|---|
| 提交 | 点击后是否立即显示已创建/已排队 | 用户不会因无响应而重复提交 |
| 等待 | 当前阶段、当前题、已完成数和心跳是否真实 | 耗时虽长，但用户知道程序在做什么 |
| 离开与返回 | 刷新、关闭页面后能否在任务中心继续查看 | 长任务不绑定当前页面 |
| 风险感知 | `formal`、`review_candidate`、`blocked` 是否易懂 | 用户不会把待复核当正式答案 |
| 文档感受 | 题答相邻、图文一致、公式可编辑、无大片空白 | 产物是否可直接阅读和二次编辑 |
| 错误处理 | 是否显示阶段、题号、影响范围和建议 | 不用猜是否需要整份重做 |

### 6.2 流程/程序角度

- 取消期间的迟到模型响应不得覆盖取消状态。
- 恢复运行只复用指纹一致的中间产物，不重做已完成高成本阶段。
- 视觉超时不得删除已通过的程序图完整性结果，也不得误升级为正式版。
- 模型复核说“需修复”但补丁无效时，风险标记必须保留到最终验收。
- 任务调用账本与任务 ID 一致，恢复运行不重复归因为新任务。

### 6.3 成本口径

每个任务至少报告：

```text
文本成功/失败请求数
视觉成功/超时请求数
生图张数
输入 token / 输出 token / 未返回 usage 次数
有效调用 / 修复调用 / 浪费调用
首结果时间 / 可下载时间 / 总耗时
每道成功题和每份 formal 文档的成本
```

人民币费用必须来自 `config/model_pricing.local.json` 中的实际火山合同单价。如未提供，只报 token、请求和耗时，不把超时或未返回 usage 的请求虚记为 0 元。

## 7. 统一判定方法

### 7.1 先看硬门禁

出现任一情况，不得进入“综合平均后算通过”：

- 漏题、错序、题答错绑或原图传错模型。
- 计算最终值、单位或科学结论高风险错误被标记为正式版。
- 图中标签、曲线、峰或相区与解析冲突。
- 正确公式被损坏、文本化、裁切或输出裸 LaTeX。
- 任务未完成、超时或待复核，界面却显示无风险正式完成。

### 7.2 再看四类收益

| 维度 | 使用者结论 | 程序结论 |
|---|---|---|
| 任务质量 | 答案是否正确、完整、好理解 | 错误是否在正确阶段被发现和归因 |
| 图像/图件 | 图是否真正帮助理解，与答案一致 | 原图绑定、视觉调用、图规格和 QA 是否可追溯 |
| 时间/体验 | 等待是否可接受、进度是否可信 | 慢是有效推理，还是超时、空重试或重复工作 |
| 成本/风险 | 额外等待和费用是否换来可感知质量 | 有效调用率、重试成本、恢复复用率和降级正确性 |
