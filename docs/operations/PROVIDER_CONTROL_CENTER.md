# 供应商运行中心

## 目标

供应商运行中心将“平台允许接入什么”“当前实际观测到什么”“任务此刻怎样执行”分成三层，避免把临时供应商波动写死到配置，也避免模型已经持续异常时任务仍无效重试。

路线的最小身份是：`供应商 + API Key 指纹 + 模型 + API 协议 + 能力`。指纹只保存 Key 的 SHA-256 前 12 位，绝不保存 Key、提示词、题目或模型响应。

## 状态和运行策略

2026-09-12 新行为：历史健康状态用于选模提示与保守调度，不再阻止用户创建任务或发起真实调用。任务创建不发送连通性探针，已选模型不因状态刷新自动替换；缺少凭据、能力/协议不匹配和内容质量门仍按原规则校验。下表中的不可用表示观测结论，任务可尝试；真实失败由原任务级有限重试、熔断、检查点和错误反馈处理。

| 状态 | 进入条件 | 任务策略 | 用户责任说明 |
|---|---|---|---|
| 未接入 | 平台支持、但本机未保存该供应商 Key | 不参与任务，也不计为故障 | 如需使用再配置 |
| 待验证 | 已批准但暂无观测 | 允许实际任务尝试 | 无 |
| 可用 | 精确路线成功一次 | 受共享动态并发及任务阶段上限约束 | 无 |
| 降级 | 精确路线出现 1–2 次供应商侧连续失败 | 只将该路线并发降到 1 | 服务商侧异常 |
| 不可用 | 精确路线连续 3 次供应商侧失败 | 提醒异常，允许用户尝试；该路线保守串行 | 服务商侧异常 |
| 账号或配置问题 | Key、权限、余额或额度问题 | 提醒检查账号，允许用户尝试 | 用户检查账号、Key 或额度 |

任意一次精确成功都会立即清零连续失败并恢复健康状态；共享池被限流后的并发上限仍逐步回升，不因单次成功跳回满额。输入过长、内容拦截、参数/结构错误和无法确定归属的普通错误只记入历史，不会污染供应商状态。

## 探测与反馈

- 任务创建前只读取状态，不再额外请求模型；状态读取失败不阻止任务。真实任务继续回写健康记录，不重写能力登记。
- 真实任务每次模型调用都反馈成功、耗时或分类后的失败；只更新实际发生问题的能力。
- 每个已配置模型以供应商通道、Key 指纹、模型及协议保存一次接入记录。已登记多模态模型通过一个图文请求同时验证文字指令和图片输入；纯文本模型验证文字；生图模型单独测试一次。历史模型统一补测，已有旧健康记录也需补一次。
- 请求前先保存开始标记，完成后保存通过或失败及分类原因；失败、进程中断、重启、后续健康变化均不自动重复或改写能力登记，也不将多模态降为纯文本。开始后未完成的记录只表示已发起，不表示验证通过。新 Key 为新接入身份。
- 启动补测后台逐个执行；运行中新增配置每五分钟补一个未登记模型。文本可用性每五小时到期检测，图片输入不再按日进行能力复验。主模型工具调用没有能力测试、白名单或过期门槛。
- 视觉探针使用随机双色图并校验左右色块，提示词不携带答案，避免文本模型伪通过。
- 参考图编辑保持手动，后续生图主动健康复测也保持手动；真实生图任务继续反馈健康记录。
- 每日读取供应商公开模型列表。读取失败保留上次成功目录并注明读取失败；新模型只作为待审核候选，列表缺失也不会自动删除已接入模型。
- 主动检测只允许在用户机本地发起；局域网监控账号可查看状态但不能产生付费调用。

## 页面展示

- 图片输入的“已登记/已验证”不随健康证据过期；模型健康汇总采用文本/生图当前观测，并保留实际图片路线异常。等待状态更新与尚无有效验证分别说明。
- 视觉探针改用纯红/蓝、绿/黄、蓝/红，避免黄橙歧义；只规范化大小写、空白与额外 JSON 字段。内容校验失败不证明能力不支持，不计供应商连续故障，不自动改写或重测历史登记。

- 默认按供应商聚合；供应商行只显示需处理的模型数，不把单模型异常描述为整个供应商不可用。模型展开后显示固定输入类型、一次接入记录、当前可用性及具体失败原因。
- 顶部显示已接入供应商、近期可用模型数、近期异常模型数及文本共享并发上限。并发按实际共享门计数，同池多个模型不重复累加，未设上限单独注明。
- 每个供应商展示能力状态标签与最近 18 次观测色块，最新观测在右；筛选支持供应商、状态和能力。
- 责任归属、原因、建议动作、当前可用性检测和最近明细放在模型下钻层。连续失败达到原阈值才显示“当前模型不能用了”，历史状态不阻止任务尝试；任务本次真实失败仍按原有限重试和停止规则处理。
- 并行能力页展示安全上限、实际动态上限、运行/等待数。共享池限流时将当前并发减半、最低 1；冷却后至少 max(3, 当前并发) 次成功才提高 1，最高不超过安全配置。各任务内部并行请求统一受共享门约束，保留任务阶段自身质量/依赖上限；不改变内容、模型、协议、思考强度和重试预算。单模型过载和读取空闲错误继续按模型/任务归因，不扩大为整池限流。
- 文本健康正常时 5 小时检查；首次供应商失败后 5 分钟检查，连续失败按指数退避最长 1 小时；恢复后 10 分钟观察，稳定后恢复低频。真实证据更新下次检查时间，每轮最多一条，生图/编辑不参与周期付费探针。
- 可信度基于近 24 小时最多 30 条证据：至少 5 条且至少 3 条真实任务记录为高，至少 3 条为中，其余为低，超过当前检查间隔标为过期。可信度衡量样本充足度，不代表模型成功概率；延迟还受输入长度和任务种类影响。普通页面显示状态、来源时间、样本量、成功率和延迟；协议和账号指纹仅在诊断详情显示。

## 自动化边界

允许自动执行：首次接入及存量模型一次性登记检测、精确路线健康观测更新、异常路线并发降到 1、检测成功恢复健康状态，以及配置安全上限内的共享并发调整。并发观测持久化，动态限额保存在当前进程内，重启按配置安全上限初始化；未配置限额的池不会自动推断安全最大值。

必须人工批准：新增或删除全局模型目录、切换 API 协议、把一个账号或模型的故障扩大到其他账号或模型。主模型工具调用是平台策略能力，不需要单独的能力审批、探测记录或开白。

## 验收要点

1. 连续 3 次供应商 503 只将相同账户、模型、协议和能力标为不可用，不阻止用户实际尝试。
2. 同模型文本失败不会影响视觉或工具调用路线；A 模型失败不会影响 B 模型。
3. 创建任务不额外探测；真实调用成功一次恢复精确路线健康状态，共享并发仍按成功窗口逐步恢复。
4. 未配置 Key 显示为中性“未接入”；已接入账号的 401、额度/权限问题明确归为用户账号配置；平台/请求错误不计供应商连续失败。
5. 运行中心默认按供应商聚合并显示近期状态轨迹；可筛选供应商、状态、能力，展开后展示实际并发、责任、建议动作和历史。
6. 局域网查看状态可用，但主动检测返回 403。
7. 状态文件不包含 API Key、题目、提示词或响应内容。
8. 方舟与其他已接入供应商遵循相同状态闭环，但不会被自动增删模型或切换协议。
9. 首次接入检测不阻塞服务启动；同一 Key 指纹、模型、协议已有一次接入记录时不重复执行，更换 Key 后重新检测；每个生图模型只在首次登记时产生一次生图检测调用。
10. 所有已选为主模型的文字模型直接允许真实工具调用；运行中心不展示该能力卡片或状态，也不设置探测、过期、审核或开白门槛。
