# 供应商运行中心

## 目标

供应商运行中心将“平台允许接入什么”“当前实际观测到什么”“任务此刻怎样执行”分成三层，避免把临时供应商波动写死到配置，也避免模型已经持续异常时任务仍无效重试。

路线的最小身份是：`供应商 + API Key 指纹 + 模型 + API 协议 + 能力`。指纹只保存 Key 的 SHA-256 前 12 位，绝不保存 Key、提示词、题目或模型响应。

## 状态和运行策略

| 状态 | 进入条件 | 任务策略 | 用户责任说明 |
|---|---|---|---|
| 未接入 | 平台支持、但本机未保存该供应商 Key | 不参与任务，也不计为故障 | 如需使用再配置 |
| 待验证 | 已批准但暂无观测 | 允许任务预检 | 无 |
| 可用 | 精确路线成功一次 | 按已验证并发运行 | 无 |
| 降级 | 精确路线出现 1–2 次供应商侧连续失败 | 只将该路线并发降到 1 | 服务商侧异常 |
| 不可用 | 精确路线连续 3 次供应商侧失败 | 阻止后续业务调用，允许精确恢复探测 | 服务商侧异常 |
| 账号或配置问题 | Key、权限、余额或额度问题 | 阻止对应账户路线 | 用户检查账号、Key 或额度 |

任意一次精确成功都会立即清零连续失败并恢复，不采用慢启动。输入过长、内容拦截、参数/结构错误和无法确定归属的普通错误只记入历史，不会污染供应商状态。

## 探测与反馈

- 每次任务创建前检测本次真正需要的文本、视觉、工具调用和生图路线。
- 真实任务每次模型调用都反馈成功、耗时或分类后的失败；只更新实际发生问题的能力。
- 文本路线 5 小时过期，后台以每 5 分钟最多一条的节奏摊平检测预算。
- 生图主动检测只允许手动触发，避免无人值守产生高成本。
- 每日读取供应商公开模型列表。新模型只作为待审核候选；列表缺失也不会自动删除已接入模型。
- 主动检测只允许在用户机本地发起；局域网监控账号可查看状态但不能产生付费调用。

## 页面展示

- 默认只显示供应商级总览，将同平台的文本、视觉、工具与生图通道聚合为一行；模型与协议按需展开。
- 顶部优先显示已接入供应商、已验证可用率、需处理能力和当前文本有效并发，不把未配置路线渲染成红色事故。
- 每个供应商展示能力状态标签与最近 18 次观测色块，最新观测在右；筛选支持供应商、状态和能力。
- 责任归属、建议动作、精确能力检测和最近明细放在模型能力下钻层，避免主页面形成长清单。

## 自动化边界

允许自动执行：精确路线临时停用、降级路线并发降到 1、精确检测成功后立即恢复。

必须人工批准：新增模型、删除模型、切换 API 协议、把一个账号或模型的故障扩大到其他账号或模型。

## 验收要点

1. 连续 3 次供应商 503 只阻止相同账户、模型、协议和能力。
2. 同模型文本失败不会影响视觉或工具调用路线；A 模型失败不会影响 B 模型。
3. 阻止后的任务预检仍能发起精确恢复探测，成功一次立即恢复。
4. 未配置 Key 显示为中性“未接入”；已接入账号的 401、额度/权限问题明确归为用户账号配置；平台/请求错误不计供应商连续失败。
5. 运行中心默认按供应商聚合并显示近期状态轨迹；可筛选供应商、状态、能力，展开后展示实际并发、责任、建议动作和历史。
6. 局域网查看状态可用，但主动检测返回 403。
7. 状态文件不包含 API Key、题目、提示词或响应内容。
8. 方舟与其他已接入供应商遵循相同状态闭环，但不会被自动增删模型或切换协议。
