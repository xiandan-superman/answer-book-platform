## 已确认的平台问题

1. 百炼 `qwen-image-max` 不是模型故障。平台把通用 `2K` 解析为 `2048*2048`，服务商明确返回该模型上限为 `1664*1664`。修正逐模型尺寸后真实生成通过。
2. WawAPI Gemini 生图不是模型名不存在。对应 Key 的 `/models` 能列出两个模型；`gemini-3-pro-image-preview` 实测从 Chat Completions 返回 Markdown 内嵌 data URI，`gemini-3.1-flash-image-preview` 实测从 Responses 返回内嵌 data URI。平台原先错误调用 `/images/generations`，修正适配并验证图片字节后两条路由均通过。
3. 连接测试原先只覆盖供应商级协议字段，模型 profile 可能把用户选择重新覆盖，形成“界面选 Chat、实际仍请求 Responses”。现连接测试和任务运行都固定到精确的供应商、模型、协议组合。
4. 2026-09-11 使用 DeepSeek 官方 Key 验证稳定别名 `deepseek-flash`：模型列表、Responses 流式结构化输出、Chat Completions 结构化输出和 Chat 图片输入均通过。该别名当前对应 V4.1 Flash；未恢复已退役的官方 `deepseek-v4-flash` 与 `deepseek-v4-flash-vision-exp`。火山方舟目录未作改变。
5. 同日进一步验证 Responses 图片输入及 `disabled/low/high/xhigh` 思考档位，并完成 1/2/4 并发、每档两轮的容量短探测；14 个请求全部成功，P95 最高约 5.35 秒。生产默认保守设为 2，4 只作为本次短请求已测峰值，仍需后续真实长任务验收。

## 上线门禁

- `config/model_protocol_verification.json` 是机器可读验证记录；服务商配置、能力注册表和协议记录必须一一对应。
- 新服务商或新模型没有真实协议观察时，配置加载与回归测试失败；只有失败记录而没有任何通过协议时，也禁止作为新模型上线。
- 本轮已有 9 个在线模型只有失败快照，按用户要求保留为“既有路线待任务前重检”，不把一次波动误判为永久下线。它们不能成为未来新模型绕过成功验收的先例。
- 支持多个已登记协议的模型才在任务页显示请求类型选择；选择值进入任务前真实预检、任务记录、恢复路径和实际调用，不做隐式协议回退。
