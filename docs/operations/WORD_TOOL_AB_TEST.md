# Word 工具 A/B 测试记录

## 当前决定

- 实验开始：2026-09-04。
- A：平台当前优化后的 Python/OMML Word 工具链；实现继续保留，不删除、不降级。
- B：直接调用 `iOfficeAI/OfficeCLI` 创建、批量编辑、保存和校验 DOCX，再叠加平台的试题、答案、公式、图片、表格、题号、字体、页眉页脚和页面排版规则。
- 默认：B。
- 切换：用户数据目录 `config/word_tool.json` 中写入 `{"variant":"A"}`；也可在启动进程设置 `ANSWER_BOOK_WORD_TOOL_VARIANT=A`。环境变量优先于用户配置，用户配置优先于源码默认配置。
- 失败策略：B 失败时不自动切回 A。自动回退会把 B 的缺陷藏进 A 的成功结果，使 A/B 统计失真；需要回退时必须明确改配置。

实际阅读并采用的上游合同包括：`sdk/python/officecli.py` 的 resident 单进程/管道与安全重连语义，`src/officecli/CommandBuilder.Batch.cs` 的默认原子批处理和 `--stop-on-error`，`CommandBuilder.Check.cs` 的 OpenXML schema 校验，`Handlers/WordHandler.cs` 的原子写回，以及 `skills/officecli-docx/SKILL.md` 中的段落、表格、图片、公式、页眉页脚和页面设置命令。

平台不运行上游安装脚本，因为该脚本还会修改用户 PATH、shell 配置和 Agent skills。平台只下载固定版本的当前系统原生二进制到用户数据缓存，先按发布清单中的固定 SHA-256 校验，再原子启用；也允许 `OFFICECLI_BINARY` 指向运维预装且已校验的二进制。

## 平台叠加规则

B 不是通用 OfficeCLI 的裸输出。以下合同仍由本平台负责，且与 A 使用同一交付门禁：

- 真题：题号与区块顺序、答案摘要、教材依据隐藏规则、公式引用、题图绑定、中文/西文字体、页面尺寸、页边距、页眉页脚和页码。
- 按题/知识点出题：题目卷、答案卷、合并卷的独立结构；题干不得泄露非 `given` 公式；选项、解析步骤、知识点、表格、题图和页码合同。
- 公式：使用 OfficeCLI 原生 equation 命令生成 OMML；按平台长期规则，公式内所有可见字符保持斜体；不得把 LaTeX 定界符留在正文。
- 图片：必须来自已存在且已绑定的真实资产，使用 OfficeCLI picture 命令嵌入并保留替代文本；缺图明确失败。
- 事务：`create → atomic batch --stop-on-error → save → validate → close`。候选失败即删除，不发布部分写入文档。
- 验收：继续运行平台已有 DOCX 结构、公式、图片、Word→PDF/PNG、页面视觉与内容一致性审计。

## 实验观测

每次真题和后台练习 Word 构建的文档工具结果记录：`word_tool_variant`、引擎、期望/实际版本、二进制 SHA-256、构建耗时、文档大小、问题数、公式/图片/表格数量、DOCX 合同结果和后续渲染结果。事件不保存题目、答案、教材或密钥正文。

比较时至少分开统计：

1. 构建成功率与 OfficeCLI 命令失败率；
2. DOCX/OMML 硬审计通过率；
3. PDF/PNG 渲染与页面一致性通过率；
4. 人工发现的内容遗漏、公式错位、图片问题和排版问题；
5. 构建耗时、运行时首次下载耗时和文档体积。

不能仅用“生成了 DOCX”判定 B 更好。只有最终 Word/PDF 可编辑、内容完整、公式和图片正确、页面验收通过，才算一次成功样本。

## 回顾与回滚

- 临时回滚：设置 `ANSWER_BOOK_WORD_TOOL_VARIANT=A` 后重启平台。
- 持久回滚：在系统用户数据目录的 `config/word_tool.json` 写入 `{"variant":"A"}` 后重启。
- 恢复 B：写入 `{"variant":"B"}`，或删除用户覆盖文件并取消环境变量。
- 回滚不删除 B 代码、OfficeCLI 缓存、B 的失败证据或历史实验记录。
- 决定结束实验前，应按上面的五类指标和三条业务线复盘，不能根据单个任务切换默认值。
