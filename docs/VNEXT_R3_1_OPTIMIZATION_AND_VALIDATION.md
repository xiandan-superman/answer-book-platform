# VNext R3.1 优化与验证报告

## 1. 版本定位

- 版本：`8.26-vnext.r3.1`
- 来源：以 R3 为基线建立的独立优化版，R3 原目录未修改。
- 边界：不新增、删除或改变低成本/高成本模型之间的选择与切换策略。
- 目标：优化模型之外的质量契约、程序修复、专业图处理、风险拦截和成本归因。

## 2. 本次优化

### 2.1 模型调用与任务归因

- CLI、GUI和恢复入口统一进入任务级模型调用上下文。
- 修复“真实任务发生了模型调用，但按任务查询成本明细为空”的归因风险。
- 不修改 provider/model 的选择，只保证既有调用被记到正确任务。

用户感知：结果内容不会因此改变，但任务耗时、调用次数和成本才能可信地用于后续比较。

### 2.2 计算题推理结构

- 计算题已有完整、结构化的【解题步骤】时，不再因缺少重复的【解析】标题而误判为缺失推理。
- 只改变“推理承载位置”的判定，公式、代入、结果与数值一致性仍独立强制审计。

用户感知：减少内容完整却因标题形式而进入候选版的情况，同时不放过真实计算错误。

### 2.3 公式片段的确定性修复

- 支持将被分割在相邻文本/公式对象中的偏导表达式重组为一个可编辑公式对象。
- 只在操作符、分子、分母和定条件都完整出现时触发，不猜测科学内容。
- 若原候选标记只由 schema/公式分段问题引起，且修复后 V4 结构校验全部通过，程序才清除该候选标记。语义或科学问题不会被清除。

用户感知：Word 中不再出现孤立的 `∂`、公式拆散或因纯格式问题产生的不必要复核标记。

### 2.4 标准专业图规格补全

- 当 schema 计划已确定为晶胞图、模型也已给出图规格，但遗漏 `structure` 时，可从题干明确的“面心立方/FCC”或“体心立方/BCC”补全该必填字段。
- 不明确晶格类型时不猜测。
- 不另造图规格，不覆盖模型的图 ID、标题和其他字段，不破坏 schema 规划层的权威性。

用户感知：明确的 FCC/BCC 标准晶胞图不再因一个必填字段遗漏而转入付费图像回退；耗时和图像模型成本在这类确定性场景中下降。

### 2.5 模型与协议配置

- 文本模型固定为火山方舟 `deepseek-v4-pro-ga-260813`，未增加高低成本模型路由。
- 该模型在当前接口下不接受生产复杂 JSON 请求中的 `response_format`，已按模型声明为“不使用 JSON mode”，改用提示词约束 JSON，避免先 400 再重试的无效请求。
- 文本模型是否支持图像按“provider + model”判定，不再因同一 provider 配有视觉模型就把图片错发给纯文本模型。

### 2.6 计算题科学错误拦截

- 将用户可见答案中的最终物理量、数值与单位，和结构化 `calculation_contract.result_quantities` 交叉校验。
- 模型复核已判定需修复，但数值补丁未通过机器验证时，显式标记 `high_risk_correctness_unresolved`，不再因“没有合法补丁”而静默通过。
- 修复 `kPa` 等数值单位被拆成公式和文字的排版问题。

用户感知：模型本身仍可能算错，但程序会把“答案摘要、推导过程、结构化结果不一致”和“高风险复核未解决”保留为审查问题，不把错答包装成正式版。

### 2.7 XRD 图文一致性与通用排版

- BCC/CsCl 确定性图的展示窗口补全到 `N≤16`，覆盖正文已列出的 `(321)`、`(400)`、`(311)`、`(320)` 等基本峰或超结构峰。
- 内容审计交叉比对最终有效图规格与用户可见解析的晶面指数，防止“文字有、图上没有”。
- 未给波长和点阵常数时，拦截“2θ 峰间距必然单调变大/变小”等超出条件的结论；只保留 `N=h²+k²+l²` 或 `sin²θ` 的相对次序。
- 本地修复只删除被程序精确定位的无支撑趋势子句，不改晶面、公式和题干。
- Word 生成将晶面指数等短科学列表中的模型换行视为行内换行，但保留真实小问换行。本题成品由 4 页压缩为 2 页。

### 2.8 文件发现与公式渲染边界

- 教材自动发现忽略 `.shared_library_manifest.json` 等隐藏管理文件，防止其被当成教材索引。
- OMML 公式审计允许 `cases` 右侧的语义性空结束定界符，但仍拒绝普通缺失或空开始定界符。

## 4. 小额真实模型验证

### 4.1 P2-02 热力学计算

- 文本模型：`deepseek-v4-pro-ga-260813`。
- 端到端耗时：351.5 s。
- 请求 13 次，成功 6 次，失败/超时 7 次；返回用量的成功请求合计 56,269 token。其中 6 次快速 400 是 JSON mode 协议不兼容，已通过模型配置消除该重试路径；另有 1 次 60.1 s 超时。
- 模型生成的环境熵变/总熵变存在严重科学错误，且正确性复核试图修正时数值补丁未通过机器验证。这是模型结论错误，不是单纯排版问题。
- 优化后的程序会同时拦截“高风险复核未解决”与“可见答案值和计算合同不一致”，不应正式交付。

### 4.2 P2-04 XRD 作图

- 文本模型：`deepseek-v4-pro-ga-260813`；视觉复核：`doubao-seed-2-1-pro-260628`。
- 累计付费账本：8 次请求，成功 6 次，超时 2 次；已返回用量 58,193 token。其中 DeepSeek 文本 5 次均成功，合计 50,502 token；豆包视觉 1 次成功，7,691 token，后续对扩展图的 2 次复核分别在 120.1 s 和 90.1 s 超时，未返回 usage。
- 首轮约 197 s 在 Word 公式门禁失败，原因是 `cases` 合法空右定界符被误拒绝；修复后恢复运行约 15 s 完成。
- 第二轮扩展图验证耗时 224.5 s，主要由两次视觉超时构成。程序因视觉复核不可用降级为待复核候选版，没有误报为正式版。
- 程序审计成功发现了不当的峰间距趋势描述，修复“假自修”后离线回放已将该句从最终答案删除，内容审计 0 问题。
- 最终程序图已人工视检：基本峰、超结构峰、晶面标签和图例完整；Word 渲染、可编辑公式和交付一致性审计均通过。但由于新图的远程视觉复核超时，当前任务状态仍诚实保留为 `review_candidate`。

## 5. 测试结果

- 全量测试：928 passed，7 skipped，1 e2e deselected。
- 平台门禁脚本：通过。包括 Python 编译、版本一致性、公式 OMML、项目完整性与全量 pytest。
- 本次修改文件的 Ruff 检查通过。仓库全局 Ruff 仍有 72 项历史基线问题，本次未把无关格式清理混入功能优化，因此不宣称全库 Ruff 为零。
- 7 项 skipped 为独立版本主动清理历史 `practice_jobs` 后缺少旧真实任务文件，不是功能失败。

机器可读门禁结果见根目录 `quality_gates_report.json`。

## 6. 成本与耗时评估

- 模型路由成本：与 R3 一致，本版本不介入低成本/高成本模型切换。
- 计费可观测性：任务级归因修复后，可用于比较单题成本、整体成本及异常重试。
- 确定性节省：明确 FCC/BCC 但图规格只缺 `structure` 时，可避免因该缺陷触发的图像生成回退；GA 模型直接跳过不兼容 JSON mode，可避免已观测的快速 400 失败请求。
- 不将视觉超时美化为“0 成本”：因平台未返回 usage，只能标记为未知计费，但对用户已产生 210.2 s 等待成本。
- 当前未配置火山方舟实际合同单价，因此报告只给出请求次数、耗时和 token，不虚构人民币金额。

## 7. 当前结论与剩余风险

R3.1 是相对 R3 的明确改进版：已用全量测试、已保存真实任务回放和 P2-02/P2-04 小额真实调用，验证它能更可靠地拦截计算科学错误、保证 XRD 图文一致、修复公式和排版问题，并对远程复核超时诚实降级。

它仍不能保证底层模型永不产生学科错误，也未解决火山视觉接口的偶发长超时。因此“最佳版本”的含义是：当前三个代码版中质量边界、风险拦截、图文一致性和用户可读性最完整的后续测试基线，而不是声称已覆盖所有学科场景。
