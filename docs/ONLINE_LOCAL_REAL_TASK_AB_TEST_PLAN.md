## 1. 测试目标

本计划不做“整个版本二选一”，而是通过真实文件和真实工作流，分阶段回答以下问题：

1. 两个版本是否完整、正确地读取了题目、公式、表格和图片。
2. 单题环境下，哪个版本的读图、计算、教材证据、绘图和 Word 交付更可靠。
3. 整卷和整批任务中，局部优势是否仍然成立，是否出现累积性漏题、错位、失败扩散或长时间等待。
4. 从用户角度看，哪个版本的等待过程、进度反馈、错误恢复、结果查看和下载体验更好。
5. 每个改进带来的质量收益，是否值得它增加的耗时、模型调用、重试、资源和维护成本。

耗时是重要指标，但不设定“越快必然越好”。如果稍慢能换来可验证的正确性、完整性和可恢复性，可判为值得；但必须记录具体代价。

### 3.2 执行顺序

- 每项先做 A/B 各 1 次。
- 任务执行顺序交替：第一项 A 先、第二项 B 先，减少供应商时段负载的影响。

- 不对所有整卷任务反复运行，避免无意义消耗模型时间和费用。

### 3.3 冷运行、热运行和恢复运行

- 质量 A/B 主结论使用隔离缓存的冷运行。
- 热缓存只在用户体验阶段单独测试，用于比较重新打开、重新导出和已完成任务查看速度。
- 检查点恢复只在第 4 阶段测试，不混入正常首跑耗时。

### 6.3 每道单题的审查层次

1. **题目和附件层**：题干、小问、图片、公式是否正确。
2. **教材证据层**：召回页是否相关，页码是否真实，证据是否支持结论。
3. **模型内容层**：模型原始返回是否已正确，错误属于知识、读图还是上下文理解。
4. **程序修复层**：程序是否修对了问题，是否错改原本正确内容，是否引入新矛盾。
5. **图件层**：是否应该画图，是否使用了真实数据，图中标注是否与答案一致。
6. **Word 交付层**：题目、解析、步骤、公式和图是否相邻，是否有裁切、错位或裸 LaTeX。

## 8. 第 4 阶段：完整用户旅程、等待感受与故障恢复

### 8.1 体验角度

本阶段不只记录“完成了多久”，还要记录用户在这段时间里看到了什么、能做什么、是否知道程序正在做什么。

| 角度 | 观察内容 | 理想信号 |
|---|---|---|
| 等待感受 | 提交后是否立即有回应；是否长时间没有变化 | 快速反馈“已排队/已开始”，持续显示真实阶段和当前对象 |
| 进度真实性 | 百分比是否倒退、卡住或提前显示完成 | 进度、后台阶段和已完成题数一致 |
| 可离开性 | 用户离开页面、刷新或重新进入后是否能继续查看 | 无需保持当前浏览器页面，任务不丢失 |
| 可控制性 | 开始、暂停、取消、重跑按钮是否符合真实状态 | 不显示虚假操作，重复点击不重复启动 |
| 错误可懂性 | 超时、524、JSON 错误、图件失败是否能区分 | 显示具体阶段、影响题号和下一步建议 |
| 恢复成本 | 故障后需要多少操作，是否重做已完成内容 | 自动复用指纹一致结果，只重做失败或变化的题 |
| 结果易读性 | 任务、质量、风险和下载状态是否易懂 | 完成、完成但有风险、失败和不可导出明确分开 |

```text
T4  内容生成完成
T5  最终审计完成
T6  下载按钮可用
T7  文件下载完成并可打开
```

由此计算：

- 提交反馈时间 `T1-T0`。
- 首次有意义进度时间 `T2-T0`。
- 首个结果等待时间 `T3-T0`。
- 内容后处理时间 `T6-T4`。
- 总可交付时间 `T7-T0`。
- 最长无任何有意义 UI 更新时间。

## 10. 判定方法

### 10.1 硬回归

出现以下任一情况，对应模块不能判为获胜：

- 漏题、错序、空父级或题答错配。
- 原图丢失、错绑、错位或视觉模型看到错图。
- 正确公式被损坏、静默文本化或输出裸 LaTeX。
- 程序伪造曲线、峰值、相区、实验数据或题干条件。
- 最终答案、计算步骤、单位和结果公式高置信度矛盾。
- 失败、取消或不完整任务被显示为完成并允许无风险导出。
- 恢复时错复用旧题或重做大量未变更的高成本结果。

### 10.2 质量与代价并列

通过硬门后，每个模块并列记录：

| 类别 | 指标 |
|---|---|
| 质量 | 正确率、问点覆盖、证据准确、读图准确、科学有效图、Word 合格率 |
| 时间 | 提交反馈、首进度、首结果、内容完成、审计完成、下载就绪和总耗时 |
| 调用 | 文本模型调用、视觉调用、生图调用、重试、备用模型调用 |
| 用户操作 | 点击、人工确认、手工重跑、离开后恢复操作 |
| 可观测性 | 最长无更新时间、错误是否定位到阶段/题号、进度是否真实 |
| 维护代价 | 新依赖、环境要求、部署复杂度、失败降级、无关学科影响 |

不强行用一个总分掩盖重要差异。每个模块的最终结论使用以下格式：

```text
结论：线上胜 / 本地胜 / 持平 / 尚无法归因
质量收益：...
时间代价：...
调用/资源代价：...
用户感受：...
硬回归：无 / ...
建议：保留线上 / 吸收本地变更组 / 回退本地变更组 / 需补充测试
```

## 11. 分阶段交付物
