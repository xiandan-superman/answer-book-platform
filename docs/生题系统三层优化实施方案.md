# 生题系统三层优化实施方案

> 目标：系统不冗杂、不沉重，模型调用不过分，质量可控且优质，同时覆盖不同用户场景和生成策略。  
> 用法：本方案作为一次性审查基线；确认后严格按第一层 → 第二层 → 第三层实现，每层通过验收再进入下一层。

## 1. 总体原则

### 1.1 保持一条主流程，不做多套页面

所有场景继续共用：

```text
提交材料 → 确认系统理解与生成方式 → 审查蓝图 → 生成与验收
```

按题出题、知识点出题、单题、多题、多文件和图片材料只改变系统的策略与默认值，不复制出多套工作台。

### 1.2 默认界面只保留三个用户决定

用户默认只需要确认：

1. 用哪些内容；
2. 怎么生成；
3. 蓝图是否可以开始生成。

页码、权重、覆盖矩阵、模型详情和高级审计放在“高级设置/风险详情”中渐进展开，不在主路径堆满控件。

### 1.3 先用程序规则检查，再按风险调用模型

- 数量、ID、题型、来源、选项、答案字段、公式/图表结构、覆盖率、重复度等，优先用本地确定性程序检查；
- 只有“答案是否正确、推理是否成立、是否超纲、难度是否匹配”等语义问题，才使用模型复核；
- 模型复核默认按整套或风险题合并调用，不为每道题单独调用一次。

### 1.4 中间结果复用，不重复解析和发送整份材料

第一阶段生成一次“来源快照”，后续蓝图、生题、重生、历史复用都按来源 ID 引用。避免三阶段反复解析 PDF/DOCX，也避免每 5 题重复发送无关的整份材料。

### 1.5 三层是先后依赖，不是三套并行功能

- 第一层解决“不能错配、不能假通过”；
- 第二层解决“能看懂、能修正、能恢复”；
- 第三层解决“更优质、更智能地适配场景”。

---

## 2. 当前与目标模型调用量

当前主流程的正常调用量约为：

```text
1 次材料分析 + 1 次蓝图 + ceil(题量 / 5) 次生题
```

例如：

| 题量 | 当前正常调用 |
|---:|---:|
| 1～5 题 | 3 次 |
| 6～10 题 | 4 次 |
| 11～15 题 | 5 次 |
| 16～20 题 | 6 次 |

JSON 自动修复只在失败时额外调用。

三层优化后的控制目标：

| 阶段 | 默认调用变化 | 目标 |
|---|---|---|
| 第一层 | 不增加 | 只修程序逻辑和质量门禁 |
| 第二层 | 不增加，并减少重复 token | 来源快照复用、按需引用材料 |
| 第三层 | 简单场景减少 1 次；风险场景最多增加 1 次整套审查 | 快速路径 + 条件质量审查 |

禁止默认采用“每题一个生成调用 + 每题一个审查调用”的重型方案。

## 3. 第一层：可靠性底座

### 定位

先修会让用户被误导、题目错配或质量状态失真的问题。不增加新页面，不增加正常模型调用。

### 实施顺序

## 3.1 统一场景策略语义

建立一个程序级策略枚举，并让前端、蓝图和后端完全一致：

### 按题出题

- `exam_targeted`：综合选中原题，生成指定总题量；
- `exam_parallel`：每道选中原题一一对应一题；
- `exam_variants`：每道选中原题生成 N 道变式。

### 知识点出题

- `knowledge_overall`：综合选中知识单元，生成指定总题量；
- `knowledge_parallel`：每个知识单元一一对应一题；
- `knowledge_item_wise`：每个知识单元生成 N 道题。

旧值在后端兼容映射，但新任务只写新枚举。确认页必须显示逐来源预计题数。

**验收：** 任意策略从页面选择到最终 `exercise_groups` 完全一致，知识点“一一对应”不再落入整体综合。

## 3.2 修正难度逻辑

- “同等难度”继承原题或来源单元的标准化难度，不再固定为全部进阶；
- 单题直接指定基础/进阶/挑战；
- 多题显示程序计算后的逐题分布；
- 无法判断来源难度时，显示“待确认”，不暗中默认。

**验收：** 基础、进阶、挑战三类原题在“同等难度”下均正确继承。

## 3.3 为每个蓝图项建立稳定 ID，修复批次错位

蓝图新增 `plan_item_id`。模型每题必须回传该 ID；程序按 ID 合并，不再按数组位置强行配对。

每批生成后立即检查：

- 本批计划 ID 是否全部返回；
- 是否重复、缺失或多出；
- 题型和来源 ID 是否与计划一致。

缺失时只补生成缺失项；异常未解决时不保存正式结果。

**验收：** 模拟任意批次少题、多题、乱序返回，后续题均不串来源、不串题型。

## 3.4 修复图形全局 ID

公式、表格和图形统一采用：

```text
exercise_id + 本题资源序号
```

网页、编辑器和 Word 都使用同一 ID。重点修复多题都叫 `g1` 时网页显示成最后一道题图形的问题。

**验收：** 多题多图时网页与 Word 的每题图形、标题和数据一致。

## 3.5 编辑、重生和导出前重新计算质量

新增轻量本地校验器，覆盖：

- 题干和答案不能为空；
- 单/多选题选项和答案格式；
- 题号、ID 和来源关系；
- 解析步骤；
- 公式、表格、图形结构；
- 资源 ID 唯一性；
- 题量和蓝图项覆盖。

人工编辑、单题重生、历史保存和 Word 导出前都运行。允许保存“不合格草稿”，但不得显示旧的“通过”，也不得以“可交付”状态导出。

**验收：** 清空答案或删除选项后质量立即变红，修复后实时恢复；不存在旧状态沿用。

## 3.6 修复单题重生上下文与模型选择

- 按 `source_mode` 选择按题/知识点专用模型；
- 重生携带该题对应的来源文字和必要图片；
- 记录本次使用的模型、来源快照版本和用户调整要求；
- 缺失来源时明确阻止，不退化为无上下文重生。

**验收：** 知识点题不再使用按题模型；有图题重生仍能读取原图。

## 3.7 历史复用先做到“不误导”

第一层先采用轻量修复：

- 历史记录明确标记来源是否完整可复用；
- 缺文件时列出文件名，要求重新上传并校验；
- 材料不完整时禁止继续，不允许静默只用剩余文字。

完整来源快照在第二层实现。

**验收：** 纯文件和混合材料任务复用时，都不会在缺文件情况下悄然继续。

### 第一层明确不做

- 不新增第二套工作台；
- 不做模型二次审题；
- 不做复杂版本树；
- 不做向量库或知识图谱；
- 不一次性重做全部 UI。

### 第一层完成标志

所有确定性错配问题消失；任何“通过”都至少代表当前结构真实合格；正常模型调用数与现在相同。

## 4. 第二层：轻量可审、可恢复工作流

### 定位

让用户能看懂系统用了什么、能最小化纠错、失败后能从已完成阶段继续。主要是数据与交互优化，默认不增加模型调用。

### 实施顺序

## 4.1 建立一次解析、全程复用的来源快照

分析阶段生成 `source_snapshot.v1`：

- 文件名、哈希、类型和解析器版本；
- 提取文本块及顺序；
- PDF 页码、DOCX 段落/表格位置；
- 图片 ID、缩略图和原图受控引用；
- 已使用/未使用页图及原因；
- 模型分析出的原题/知识单元与原文定位。

后续不再重新解析原文件，只传与当前蓝图项相关的文本块和图页。

**收益：** 不增加调用次数，减少重复 token、PDF 转换和图片传输；历史可完整复用。

## 4.2 范围确认页支持“最小纠错”

默认仍是简洁勾选列表；每项只增加：

- 展开原文/页码/图片；
- 编辑标题和知识点；
- 合并、拆分、手工新增；
- 只重新分析本项。

高级操作折叠，不让普通用户一进入就面对复杂表单。

**调用控制：** 编辑、合并、拆分默认纯本地；只有用户点击“重新分析本项”才增加一次模型调用。

## 4.3 蓝图增加紧凑覆盖视图

主列表保持现有逐题卡片，只新增一个可折叠“覆盖与分布”摘要：

- 每个来源/知识单元覆盖几题；
- 题型分布；
- 难度分布；
- 是否有遗漏；
- 是否触发 20/30 题上限截断。

支持增删、排序和修改来源关联，但不默认展示大型二维表；只有多来源任务才提供完整覆盖矩阵。

**调用控制：** 蓝图人工修改不调用模型；“重新设计整份蓝图”才调用一次。

## 4.4 建立阶段检查点和继续入口

持久化四类状态：

```text
来源快照 → 已确认范围 → 已确认蓝图 → 生成结果版本
```

支持：

- 从已完成分析继续；
- 从已确认蓝图继续生成；
- 当前阶段重试；
- 切换模型后只重试失败阶段；
- 取消排队/运行任务；
- 服务重启后恢复可恢复状态。

不做任意指令级断点续传，只做阶段级续跑，保持实现简单。

## 4.5 轻量化任务轮询和存储

- 轮询接口只返回状态、阶段、进度、错误和结果是否就绪；
- 完成后再单独拉取结果；
- 不在每次轮询中返回文件 Base64；
- 临时任务按保留期清理；
- 同一请求增加幂等键，避免重复点击和多窗口重复付费。

## 4.6 错误信息给出下一步动作

错误统一分为：材料解析、模型连接、模型输出、结构校验、语义质量、导出。每类提供 1～3 个可执行动作，例如：

- 重试当前阶段；
- 切换模型；
- 只分析指定页；
- 重新上传缺失文件；
- 补生成缺失计划项；
- 下载诊断编号。

### 第二层明确不做

- 不做任意时间点自动版本树；
- 不默认显示全量技术日志；
- 不自动对每项反复调用模型；
- 不把所有高级参数放在主界面。

### 第二层完成标志

用户可看到来源、可修正范围、可理解蓝图覆盖、可从阶段检查点继续；默认调用次数不增加，材料 token 和重复解析显著下降。

## 5. 第三层：自适应场景与优质质量控制

### 定位

在可靠、可恢复的基础上提高内容质量，并通过场景路由控制复杂度和调用量。

### 实施顺序

## 5.1 场景路由器：只决定默认路径，不创建新页面

根据来源快照判断场景：

| 场景 | 默认路径 |
|---|---|
| 单一纯文字原题 | 快速单题路径 |
| 一套多题试卷 | 选题 + 三种按题策略 |
| 只有知识点名称 | 知识边界 + 知识策略 |
| 教材章节/多知识单元 | 单元选择 + 覆盖策略 |
| 多文件或有图材料 | 显示来源完整性与页图选择 |
| 高题量 | 分批生成 + 批次完整性门禁 |

路由器只预设最合适的策略、提示和控件，用户仍可切换。

## 5.2 简单场景快速路径，减少一次模型调用

对“单一、纯文字、低风险”的原题或知识点，可把材料分析和蓝图设计合并为一次模型调用，然后在同一页面让用户同时审查来源理解和蓝图。

复杂场景仍保留独立分析 → 范围确认 → 蓝图。

目标调用量：

```text
简单场景：1 次分析+蓝图 + ceil(题量/5) 次生题
复杂场景：1 次分析 + 1 次蓝图 + ceil(题量/5) 次生题
```

快速路径必须满足：单一来源、无图片、无拆分歧义、未触发不确定项。否则自动走完整路径。

## 5.3 三层质量门禁

### A. 本地结构审计（始终执行，0 次模型调用）

- 字段、选项、答案格式；
- 公式/图表可渲染；
- 来源和蓝图 ID；
- 题量、覆盖、重复文本；
- 网页与 Word 资源一致性。

### B. 规则与计算审计（按题型执行，0 次模型调用）

- 单选唯一答案、多选答案集合；
- 数值答案和单位格式；
- 可机器复算的公式/计算；
- 题型与答案结构匹配；
- 难度和步骤数量的基础一致性。

### C. 语义质量审查（条件触发，最多 1 次整套调用）

只在以下条件触发：

- 用户选择“正式质量审查”；
- 有挑战题、综合题、作图题或高风险不确定项；
- 本地门禁发现无法判断的语义风险；
- 任务用于正式交付而非草稿练习。

把整套题或风险题合并为一次审查，输出逐题风险和修复建议，不默认每题单独调用。

## 5.4 风险题定向修复，不整套重生

- 低风险：用户确认后保留；
- 可程序修复：本地自动修复；
- 语义问题：只把风险题按最多 3～5 题一批重生；
- 修复后只重审被修改题及其来源关系。

避免一题有问题导致整套重跑。

## 5.5 轻量版本与差异

只保存关键版本：

1. 初次生成；
2. 人工确认保存；
3. 正式导出版本。

单题重生和编辑先进入草稿差异，用户确认后并入版本。支持撤销到最近一个关键版本，不构建复杂分支树。

## 5.6 完整交付检查

正式导出前统一显示：

- 来源是否完整；
- 蓝图覆盖是否完整；
- 本地结构/规则审计结果；
- 是否做过语义审查；
- 尚未接受的风险；
- 模型、来源快照和结果版本。

用户可导出草稿，但文件名和首页明确标注“草稿/存在风险”；只有通过正式门禁才标记“可交付”。

### 第三层明确不做

- 不默认双模型互审；
- 不默认每题单独审查；
- 不追求完全自动替代人工教研；
- 不把低风险练习任务强制升级为昂贵流程。

### 第三层完成标志

简单场景调用更少，复杂场景覆盖更完整；正式任务具备条件触发的语义质量审查；风险题可定向修复，质量与成本均可解释。

---

## 6. 三层实施总顺序

| 顺序 | 层级 | 核心产出 | 默认模型调用变化 | 进入下一层条件 |
|---:|---|---|---|---|
| 1 | 可靠性底座 | 策略、难度、批次、图形、质量状态、重生和复用不再失真 | 0 | P0 场景测试全部通过 |
| 2 | 轻量可审可恢复 | 来源快照、最小纠错、覆盖摘要、阶段续跑、轻量任务 | 不增加，token 下降 | 历史复用与重启续跑通过 |
| 3 | 自适应优质质量 | 快速路径、三层质量门禁、风险题定向修复、正式交付检查 | 简单场景 -1；风险任务最多 +1 | 质量、成本和多场景回归达标 |

---

## 7. 一次审查时只需确认的决策

建议本次只确认以下 5 个产品决策，确认后实现过程中不再反复讨论细节：

1. 是否同意按“第一层 → 第二层 → 第三层”严格推进；
2. 是否同意知识点和按题使用独立策略枚举，但共用一套工作台；
3. 是否同意默认只做本地质量审计，语义模型审查按风险/正式交付触发；
4. 是否同意历史保存来源快照，而不是永久保存无管理的完整 Base64 job payload；
5. 是否同意简单纯文字场景在第三层启用“分析+蓝图一次调用”的快速路径。

如这 5 项整体通过，可直接按本文顺序实施；每层只做验收，不重新讨论总体方向。

---

## 8. 最终推荐

不要一次性增加大量功能。先让系统“不会错、不会假通过”，再让用户“看得懂、改得了、接得上”，最后才增加“更聪明的场景路由和语义质量审查”。

最优平衡是：

```text
默认轻量流程
+ 本地确定性质量门禁
+ 可复用来源快照
+ 风险触发的一次整套语义审查
+ 只修风险题
```

这样既能保持系统简洁，又能覆盖单题、整卷、知识点、教材、多文件和有图材料；普通任务不增加模型调用，简单任务还可少一次调用，正式高质量任务最多增加一次合并审查。
