# 模型能力与任务适配表（审阅草案）

> 状态：机器可读注册表、同步门禁、平台级上下文计划和主要任务链能力校验已在本地源码实现；自动选模仍未启用
> 建立日期：2026-08-27
> 适用范围：电脑网页端中所有调用大模型的生题、真题处理、审核、图片生成任务

## 1. 这张表解决什么问题

平台不能只记录“模型是否支持图片”，也不能根据模型名称临时猜测能力。每个模型必须同时回答以下问题：

1. **能接收什么**：文本、图片、音频、视频、原生 PDF/Word，还是仅能接收平台解析后的文本。
2. **平台应怎样给**：直接传原始内容，还是先 OCR、分页渲染、提取结构、压缩或分批。
3. **适合做哪一步**：材料理解、蓝图规划、正式生题、答案生成、复核、图片生成等不能混为一个“文本生成”。
4. **输出怎样保证可用**：是否原生支持 JSON、最大可靠输出、是否需要分批、修复、二次校验或交叉复核。
5. **不满足时怎么办**：阻止任务、换用专用模型、先做预处理，还是允许降级且告知用户。

本表分为三层：

- **模型原生能力**：服务商和模型本身支持什么。
- **平台输入编排**：平台实际向模型发送什么，不能把“平台能解析 PDF”写成“模型原生支持 PDF”。
- **任务适配结论**：某个任务步骤允许、推荐、限制或禁止使用该模型。

## 2. 证据等级与状态

| 等级 | 含义 | 能否进入自动路由 |
|---|---|---|
| A | 官方能力、平台能力调用和对应真实任务流程均已通过 | 可以 |
| B | 官方能力或平台能力调用已有证据，但真实任务质量基线尚未完整通过 | 不可以；只能显式选择并按已验证边界调用 |
| C | 仅来自当前项目配置、代理商说明或模型名称 | 不可以；只能由用户显式选择并按保守策略调用 |
| D | 未知、未验证或验证已过期 | 不可以；不得宣称支持 |

能力字段必须使用 `支持 / 不支持 / 平台转换 / 待验证`，不允许用空值暗示支持。

## 3. 平台任务阶段与最低能力要求

| 任务阶段 | 模型必须接收的内容 | 必需能力 | 输出合同与质量门槛 | 不合格时的处理 |
|---|---|---|---|---|
| 练习材料理解 | 用户要求、截图/扫描件、解析文本、页码与图片顺序 | 有图片时必须视觉理解；纯文本可用文本模型 | 严格 JSON；逐页/逐图引用；区分原文、识别结果与推断 | 改用已验证视觉模型；无视觉模型则阻止，不得只看文件名或忽略图片 |
| 练习蓝图规划 | 已确认的结构化材料快照、题量、题型、难度、知识点和来源约束 | 长文本理解、结构化输出、约束遵循 | 题量守恒、知识点覆盖、题型/难度合计一致 | JSON 修复后仍不一致则重试或换模型 |
| 正式生题 | 蓝图、结构化来源证据、必要的原图、格式规范和已有题目去重上下文 | 稳定长输出；若题目依赖图形，主模型也必须支持视觉 | 严格题目结构；答案可解；引用可追溯；批次合并无重复 | 分批生成；规则校验失败则定向重生；视觉依赖不能降级成纯文本猜测 |
| 局部重生/修订 | 原题、失败原因、只允许修改的字段、相关来源 | 指令遵循、局部编辑、结构化输出 | 未指定字段保持不变；题号和引用稳定 | 差异检查失败则拒绝覆盖原题 |
| 真题题面理解 | 原始题目图片/文本、题号、选项、图表 | 图片题必须视觉理解；多页题需要跨页关联 | 题面、选项、公式、图表关系完整；保留不确定项 | 低置信度进入人工确认，不直接进入答案生成 |
| 证据与推理 | 已确认题面、教材/讲义证据、允许使用的知识范围 | 长上下文、推理、引用保持 | 结论与证据分离；引用可定位；不补造缺失条件 | 缺证据时明确返回“证据不足”，不得强答 |
| 答案生成 | 已确认题面、证据、评分与讲解要求 | 推理、长输出、数学/格式稳定性 | 答案、步骤、评分点一致；选择题答案与解析一致 | 规则校验 + 正确性复核；失败则定向重生 |
| 正确性复核 | 题目、答案、解析、证据和生成模型结论 | 独立判断、结构化判定 | 返回问题位置、严重程度、可执行修复意见；不能只给总分 | 与生成模型尽量分离；高风险冲突交人工 |
| 图形需求判断 | 题目语义、已有图、拟生成图的教学作用 | 视觉理解（有原图时）、结构化输出 | 明确“需要/不需要”、图形类型、必须元素、禁止元素 | 不确定时不自动生成装饰图 |
| 教学图片生成 | 经审核的图片提示、比例、尺寸、文字与构图约束 | 图片输出 | 内容与题意一致；文字/标注可读；不得替代题目正确性审核 | 生成后由视觉理解模型复核，不通过则重绘 |
| 输出修复 | 原始输出、目标 schema、解析错误，且不追加新知识 | 结构化输出 | 只修复格式，不改变事实内容 | 两次失败后换模型或终止，不能无限重试 |

## 4. 输入编排规则

| 用户输入 | 平台标准处理 | 发给模型的内容 | 关键限制 |
|---|---|---|---|
| 普通文本 | 清洗无效空白，保留标题、题号、公式与段落层级 | 文本 + 来源标识 | 不得把不同文件无边界拼接 |
| 截图/照片 | 校正方向、压缩到模型限制内，保留原顺序 | 对已验证视觉模型直接传图片，同时附任务说明；必要时附 OCR 辅助文本 | OCR 不能替代原图；模型必须知道 OCR 可能有误 |
| 扫描 PDF | 本地逐页渲染并提取文本 | 页图 + 分页文本 + 页码映射 | 当前平台默认不依赖模型原生 PDF；跨页题不可拆散 |
| 文本 PDF | 本地提取文本，图表页同时渲染 | 结构化分页文本；有图表时附页图 | 只传提取文本会丢图表、版式和公式关系 |
| Word | 本地提取段落、表格、图片及其顺序 | 结构化文本 + 必要图片 | 当前平台不把 DOCX 原文件直接交给模型 |
| 多文件 | 先建文件清单与来源边界，再按题目/章节切块 | 每块均带文件名、页码、内容类型和前后关系 | 不得超过模型上下文后静默截断；必须分批并汇总 |
| 已有题目/历史结果 | 提取用于去重或修订的最小必要信息 | 题干指纹、知识点、答案轮廓或完整原题（按任务决定） | 避免无关历史挤占上下文 |
| 图片生成结果 | 保存原图及生成参数，再交视觉模型检查 | 图片 + 原题 + 图片规格 | 图片模型的“生成成功”不等于内容正确 |

当前平台对 PDF/Word 主要采用本地解析或渲染，因此下表中的“PDF/Word：平台转换”与“模型原生文件输入”是两个不同能力。

## 7. 当前能力表暴露出的平台缺口

1. `model_capabilities` 目前只表达 `text/vision`，不足以指导任务。
2. `supports_vision` 仍有服务商级字段，容易把一个模型的能力错误扩散到同服务商其他模型。
3. 当前缺少每模型上下文、图片数量/大小、结构化输出方式、推理要求、任务适配和验证日期。
4. PDF/Word 的本地转换能力与模型原生文件能力尚未在配置中分离表达。
5. 部分模型标签或配置声明“已实测”，但缺少可复现测试记录、样本版本和日期。
6. 当前主要依赖调用时报错，尚未在任务开始前完成输入兼容性和预计容量检查。
7. 当前视觉回退主要解决“看懂来源”，并不自动保证后续正式生题模型仍能看到必要原图。
8. 图片生成后缺少统一的视觉复核合同，容易把接口成功误认为教学内容合格。

## 8.1 已落地的平台级上下文编排

- 来源题现在保存 `content_refs`、`required_evidence_refs`、`visual_evidence_refs` 和不可由摘要替代的视觉依赖合同。
- 蓝图项按绑定来源确定性继承证据，不再让模型自由决定后续是否需要原图。
- 正式生题优先按显式图片证据附图，关键词判断只保留给旧蓝图兼容。
- 语义质量审查会重新取得同一来源图片；图片不完整时不能标记为已审查。
- 每次材料分析、蓝图、生成和语义审查都记录预计输入、任务质量预算和遗漏证据。
- 正式生题批次超过模型任务质量预算时会继续按题拆小，不以官方最大上下文作为组批目标。
- 统一模型客户端现在为每次文本或多模态调用生成上下文计划，并在发出请求前检查任务适配、输入模态、图片数量、必要证据和阶段质量预算。
- 真题解析主链已接入题面理解、考查内容规划、教材证据确认、答案生成与正确性复核阶段；每次调用保留绑定题号和上下文计划。
- 格式修复、插图结构规划、作图代码生成、插图修复与视觉审查也使用同一能力门禁，避免辅助流程绕过模型能力表。
- 按题生题与知识点生题共用同一生成管线，两种入口都继承来源证据合同、分批预算和语义审查门禁。
